# HD 资源的实际 LIB 身份

`js/hd-lib-identity.js` 对引擎当前 `dynLib` 十六进制内容解码后计算 SHA-256。`baye/libpath` 只是用户首选的加载路径；IndexedDB 缓存可能提供不同内容，因此路径、文件名和 Mod 显示名都不能授权 HD 素材。

地图、人物立绘、战场地形和 SPE 共用同一个字节身份，各自检查自己的资源来源和回退条件。共享模块不选择美术，也不判断 Mod hook 的含义。现有原生成套 WASM 不因这批前端修改而重编。

## 只读契约

```js
const state = BayeHdLibIdentity.read();
// { status, generation, sha256, byteLength, reason }
const unsubscribe = BayeHdLibIdentity.subscribe(onChange);
const current = BayeHdLibIdentity.isCurrent(state);
```

快照被冻结；状态为 `unavailable`、`pending`、`ready`、`invalid` 或 `error`，仅 `ready` 有完整摘要。订阅只通知变化，没有隐式首次通知；消费者需先读取当前状态。`isCurrent` 重新读取真实内容，比较代次、状态和摘要。

首次观察和实际源变化增加代次。同一源的多个消费者只共用一次校验。没有内容、非十六进制、奇数长度、超过 32 MiB、读取失败、缺少 crypto 或摘要失败时，都没有可信身份。订阅回调出错不影响其他消费者。

校验完成前再次检查实际内容；即使期间没有轮询，旧结果也不会认证新库。原生引擎会替换 `window.Promise`，模块直接使用 crypto 返回的原生 promise。图片、资源 JSON、人物姓名索引和地图对齐还须保留各自的视图与身份代次。

## 消费者的授权和回退

| 消费者 | 附加要求 | 回退 |
|---|---|---|
| 中国 LCC 大地图 | 实际标准库摘要；manifest、城市地理表摘要一致；全部城市编号、原生名称、原生 x/y 同时匹配 | 撤掉 HD 地图与交互，原生 LCD 继续接收玩家输入 |
| 装饰道路 | 地图已授权，邻接文件来源摘要一致 | 只撤道路，不改变原生出征可达性 |
| 人物立绘 | manifest 摘要与实际库一致；参考索引也匹配该摘要；当前时期与人物 ID 有精确映射 | 缺 HD 用精确参考，缺参考或未知库直接 LCD |
| 战场地形 | 标准库摘要、真实完整地图与单位交叉核对；没有自定义地形解释 hook | 中性未知地形，不解释增益或战斗结果 |
| SPE 图片槽 | 素材 manifest 摘要、实际资源指纹、原生范围和合成帧完全一致 | 同一原生显示提交的 LCD；不自行推进动画 |

标准库为 `libs/dat-mod.lib`，实际 207195 字节，SHA-256 `3bd20146084054163d045c90987c756a6a210664e78253cc56bc4a274727903e`。正确字节从其他路径或缓存载入仍可授权；未知库即使首选路径是这个名字也不能授权。地形专用 hook 不全局禁止地图或立绘。

地图 JSON 使用本批 `20261008i` 版本，避免旧元数据滞留；已有地形图片无需重新下载。入口先加载身份模块，再加载消费者。本批修改的前端脚本为 `20261008i`；原生四件产物仍为上一批 `20261008h`。

`hd-portrait-smoke.html` 明确是没有运行游戏的素材预览，拥有独立缓存空间和画面标记，不提供伪造摘要，也不能将预览图片迟到结果带入随后运行的游戏。导出脚本读取实际页面 `dynLib` 并记录摘要；来源不明时不写旧索引。更换来源后不继承另一个库的 HD 路径。

## 归属与属性

`g_PlayerKing` 是零起始人物编号；城池 `Belong` 是人物编号加一，0 才是无主。有效 255 等高编号是普通君主归属；缺失、越界或城市 65535 保持未知。

人物当前 `Belong=65535` 才表示俘虏，0 表示在野。`OldBelong=65535` 只表示原归属未知，不能当成俘虏。姓名必须由实际名单读取，不从立绘文件名或同名菜单猜 ID。未知库或自定义属性解释时，详情保留真实原始码，不套原版性格、兵种或城况文字。

城池详情分为归属与城况、民生与发展、资源与军备，队列内部偏移不展示为属性。人物详情只旁读精确匹配当前原生名单与队列的高亮项，显示真实能力、体力、兵力、基础兵种和两件装备。未导出的 Mod 属性、装备派生兵种及独立帮助人物身份仍待补齐。

## 验证边界

专项使用实际 LIB 字节、真实 WebCrypto SHA 和受控迟到响应；绘制或路由单元测试使用明确的只读夹具，不能冒充原生流程。

`node scripts/test-hd-runtime.mjs --library-identity` 在独立浏览器与 IndexedDB 中执行真实原版和真实 `sc-mod.lib` 载入：相同字节不同首选路径、实际 Mod 缓存配原版首选路径、再恢复原版。Mod 的真实难度选择和确认菜单通过玩家按键处理；未知身份下原生城池菜单仍可操作。该专项不代表完整 Mod 战斗或四时期战役已验收。

`sc-mod.lib` 脚本添加可枚举 Array 原型方法，实际浏览器暴露旧 IndexedDB SDK 将这些方法误当待初始化事务的问题。修复只对 SDK 的等待数组使用数值迭代，保持 Mod 方法和游戏内容。SDK 专项与真实缓存流程共同验证，不删除 Mod 原型来绕过问题。

最终 Windows 全量 318 项（含编译执行 C）通过，真实核心/缓存/HUD 27 点、战斗 51 点、SPE 18 点通过；具体源码与产物身份、原生快照、截图及未覆盖范围见[本批证据](validation/m4-library-identity-20261008.json)。
