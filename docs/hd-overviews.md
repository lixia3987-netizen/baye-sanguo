# 战场 VIEW 与主地图概览的原生观察契约

更新日期：2026 年 10 月 8 日。本批原生观察桥及高清界面已通过真实 PC VIEW10 与主地图小地图流程；实际场景、源码/产物身份及覆盖限制见[本批验收](validation/m4-overviews-20261008.json)。人物、道具与 HELP9 的契约继续见[高清详情数据](hd-details.md)。

## 观察与输入的边界

`baye.hd.view()` 和 `baye.hd.miniMap()` 是独立快照，不借用 HELP9 文本或根据当前焦点猜测内容。快照只在实际原生绘制调用处捕获，读取不会重新调用姓名、资源文本或 Mod hook。原生列表切换、分页、关闭、消息等待和触控协议保持原样；高清按钮只按玩家操作发送已有键码，不自动翻页、确认或关闭。

观察桥维护自己的活动标志、序号与代次，不写人物、粮草、城市、战斗结果或原生地图游标。`generation` 必须等于当前 `g_hdDetailGeneration`；内容序号与真正的输入序号共同决定按钮归属，不能只凭界面仍显示或输入种类相同发送旧操作。

Web 原生 `call_hook_a_observed` 在原有的唯一 hook 查找路径中记录是否存在 hook，并执行原有调用与异步 action 循环；不追加 `has_hook` 或其它 JavaScript 属性探测。即使存在的 hook 返回 `-1` 让默认绘制继续，观察仍标记为 `custom`，不假定 hook 没有改变画面或状态。非 Web 后端沿原调用一次并保守标记自定义；这不代表已经完成真实设备验收。

## 战场 VIEW10

战场 SEARCH 进入原生 `FgtShowView`，对应 `BAYE_HD_FIGHT_INPUT_VIEW=10`。默认显示敌方，左右键切换双方并回到第一页；上下键沿原生分页，ENTER/EXIT 返回。原生触控的横向滑动切方、纵向滑动翻页及点击退出继续由原生处理。

每页大小来自真实 LCD 工作区和字号：`(WK_EY - (HZ_HGT * 2 + 6)) / HZ_HGT`。160×96、12 像素字高的基准每页为 5 行，高清视口不会改成另一套页长。原生收到方向键后，即使已经到边界、页码未变，仍产生新的输入 ACK；闪烁点阵的定时刷新不产生 ACK，也不推进观察页序号。

公开快照协议版本为 1：

| 字段 | 原生含义 |
|---|---|
| `active/complete/custom` | 实际 VIEW 是否活动、当前默认页是否完整、安全结构化展示是否受自定义 hook 影响 |
| `seq/generation/detailGeneration/inputSeq` | 本次实际页、世界/资源代次及当前 VIEW10 输入归属 |
| `force/pageStart/pageSize/totalCount/rowCount` | `force=0` 为玩家、`1` 为敌方；页起点、原生页长、连续名单总数及当前实际行数 |
| `width/height/days/playerMode` | 原生战场尺寸、回合天数和原生作战模式 |
| `leaderPerson/title/daysText/positionsText/factionText` | 实际君主零基 U16 编号及同一次原生绘制的完整标题、天数、位置和势力文字 |
| `foodKnown/food/foodText` | 原生允许显示的粮草与实际文字；敌粮未获知时 `foodKnown=0, food=0` |
| `rows` | 当前实际页的 `{slot, personIndex, name, text, arms}`，编号零基 U16，兵力 U16 |
| `points` | 原生闪烁点阵的 `{slot, personIndex, x, y, state}`；不为点阵额外读取姓名 |

双方名单从各自 10 个 `GenArray` 槽的首个零结束，不跨过空槽拼出新名单。列表保留原生仍列出的死亡将领；点阵单独按原生规则排除 `STATE_SW`。不能因为某行没有点就删掉该行，或把所有状态当作同一类有效单位。

玩家粮草来自原生 `MProvender`。敌方只使用原生已经允许获知的 `g_EneTmpProv`；该值为零时保留原生未知文字和零数值，不读取、推算或泄露 `EProvender`。势力文字保留实际资源输出，不自行拼接君主名和后缀。

`g_hdViewRowNames` 为 10×32 字节，`g_hdViewRowText` 为 10×64 字节。两者通过 `DEFADD_U8ARR` 绑定，桥按槽分别解码 GBK；内嵌 NUL 是每槽终止符，不能把整个缓冲绑定成一条 GBK 字符串，否则后续行会丢失或错位。单个标题等文字仍使用单字符串绑定。完整姓名单独捕获，`text` 保留原生最终行格式，包括原生在字节偏移 8 写入兵力的排版。

结构化页必须满足当前代次/输入、合法人数与页界、行数和槽位一致、编号有效、坐标在实际地图内等检查。文本超出固定槽、未终止、字段缺失、换代或存在 `didShowFightSituation` / `didRefreshFightSituation` 自定义 hook 时，保留原生 LCD。默认完整页使用高清界面，经典对照由玩家明确选择，并在同一概览会话分页时保留选择。

## 主地图小地图与高清“地图概览”

主地图 `GetCitySet` 在实际 map wait 中接收 SEARCH，调用一次原生 `showMiniMap`。默认分支加载并绘制 `TACTIC_ICON=75`、图片索引 0。标准 LIB 的图片头为 84×64、`count=1`、`mask=0`；原生 `gam_drawpic(..., 1)` 的最后参数是绘制模式，不是图片头的掩码位。

资源 75 是静态小地图图片。原生这次绘制没有动态查询城市归属、增加城点或将城点变成选择入口。高清“地图概览”在已经通过实际标准 LIB、地理来源与全部城市表校验时，复用已授权的高清主地图及全部真实城市，明确表示**当前主图概览**；这些动态城点不声称来自原生资源 75，也不新增原生小地图选城能力。

公开快照协议版本为 1：

| 字段 | 原生含义 |
|---|---|
| `active/complete/custom/defaultDraw` | 实际覆盖层活动、默认资源元数据完整、实际 hook 存在情况及是否执行默认绘制 |
| `seq/generation/detailGeneration/mapInputSeq` | 独立小地图进入序号、当前代次和真实主地图输入归属 |
| `resourceId/imageIndex/width/height/mask` | 实际资源 75、索引 0 及图片头元数据，掩码不由绘制模式推导 |
| `cursorX/cursorY/viewX/viewY/viewWidth/viewHeight/city1` | 实际主地图游标、视口和当前一基城市编号；只读，不作为原生静态图片包含城点的证据 |

元数据校验使用实际已载资源头、索引、载荷和物理文件边界，验证图片头及完整图片字节，并恢复资源流游标，包括文件末尾位置。坏尺寸、掩码、数量或范围不能产生完整快照；这项局部校验不等于已经加固整个旧 LIB 解析器。

未知或尚未校验的实际 LIB、未知地图布局、资产未就绪、自定义 `showMiniMap` 和不完整快照保留经典 LCD。首选路径相同不代表实际加载内容相同，不能用 localStorage 的偏好替代实际 LIB 授权。

原生 `tpicflag` 活动期间，任意字符键仅关闭覆盖层并重绘主地图；该键不继续移动游标或选择城市。触控抬起同样关闭，按下与移动不导航。高清返回沿这一次真实退出处理；显示或关闭观察窗口不主动发送按键。每次实际重开都有新的小地图 `seq`，即使 `mapInputSeq` 没变也不能复用上次按钮。

## 退休与验证

离开输入等待、打开报告/其它菜单/帮助、进入或离开战斗、世界及资源重置都会使对应观察退休。原生局部捕获同时保留代次、输入序号和退休票据；hook 中途换代或报告接管后，旧局部数据不得重新激活快照。定时闪烁只更新原生 LCD，不创建新的高清操作归属。

按钮从 pointerdown 到 click 保留所属快照票据，关闭或新页到来不能把旧按下动作转给新按钮。小地图同时记录本地表现代次；隐藏或经典模式关闭后，即使恢复同一个原生 owner，旧按下票据也不会重新有效。发送前再次检查完整 VIEW 或小地图归属；过期操作发送零键。经典对照开关只改表现，不发送游戏键，也不关闭原生窗口。

`test-hd-overviews-engine.mjs` 编译执行实际绘制/资源/生命周期函数，并覆盖生产 U8 多槽绑定及原有唯一 hook 查找路径；`test-hd-overviews-bridge.mjs` 验证公开字段、GBK 字节槽、代次变化与错误类型回退。界面专项另检查原生页、边界 ACK、旧按钮和经典对照。真实验收需另外保存双方切换、上下翻页与边界、返回/重开、敌粮未知、报告接管、主地图 SEARCH 及任意键/触控退出、未知 Mod 回退的输入与画面证据；最终运行统计与截图由本批验收记录补齐。
